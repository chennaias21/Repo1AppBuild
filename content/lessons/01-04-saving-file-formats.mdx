## Why this matters

One format choice can delete every formula in your workbook, silently, every time you save. People lose months of work to it — not because they didn't know, but because the warning appears so often they stopped reading it. Four formats, and the rule takes thirty seconds to learn.

## How it works

A **workbook** is the file. A **worksheet** is one page inside it. One workbook holds many sheets.

| Format | Holds | Use it for |
|---|---|---|
| **.xlsx** | Everything — sheets, formulas, formatting, charts, pivots | **Your default. Always, unless there's a reason.** |
| **.xlsm** | Same, plus macros | Only when you actually have macros (Lesson 8.8) |
| **.csv** | **One sheet. Values only. No formulas, no formatting.** | Moving data between systems |
| **.pdf** | A fixed picture of the output | Sending to people who shouldn't edit it |

### The CSV trap

CSV is plain text. It has no concept of multiple sheets, formulas, colours or charts. Save an .xlsx as .csv and Excel throws all of that away — keeping only the active sheet's values.

Excel does warn you. The warning appears *every single time you press Ctrl+S*, so people learn to click through it.

<Callout type="warning">
Your HRMS exports CSV. Your payroll system imports CSV. That's fine — CSV is a good transport format. But the moment a CSV lands on your machine, press <Kbd>F12</Kbd> and **save it as .xlsx before you do any work on it.** Every formula you build inside a CSV is destroyed on every save.
</Callout>

The correct journey for any export:

```
attendance_export.csv          ← what the system gave you (values only)
        ↓ F12, save as .xlsx
Attendance_Sep2026_Working.xlsx ← your formulas live here
        ↓ File → Export
Attendance_Sep2026.pdf          ← what your manager receives
```

### AutoSave is not what you think

If the file is in OneDrive or SharePoint, Excel autosaves continuously and keeps version history. **If it's on your own drive, it does not.** It keeps an AutoRecover snapshot, which is crash recovery, not saving.

Check the AutoSave toggle at the top-left. Greyed out means you are responsible for pressing <Kbd>Ctrl</Kbd>+<Kbd>S</Kbd>.

<Callout type="tip">
Change AutoRecover from 10 minutes to 2, at **File → Options → Save**, and tick *Keep the last AutoRecovered version*. There's no downside, and the default means a crash can cost you ten minutes.
</Callout>

## Do it

1. Press <Kbd>Ctrl</Kbd>+<Kbd>N</Kbd> for a new workbook. Type a few numbers.
2. Press <Kbd>Ctrl</Kbd>+<Kbd>S</Kbd>. Name it properly — `HR_Headcount_Sep2026`, not `Book1`. Check the type reads **Excel Workbook (\*.xlsx)**. Save.
3. From now on <Kbd>Ctrl</Kbd>+<Kbd>S</Kbd> saves silently. Press it constantly.

### Watch a CSV destroy your work

4. Add a second sheet (<Kbd>Shift</Kbd>+<Kbd>F11</Kbd>) named `Summary`. On it, put `=SUM(Sheet1!A1:A5)`.
5. Press <Kbd>F12</Kbd>. Change the type to **CSV (Comma delimited)**. Save. Read the warning, then accept it.
6. Close the file and reopen it. **The Summary sheet is gone. The formula is gone.** Only one sheet of values remains.

<Shot id="1.4.2" />

7. That's what happens on every save inside a CSV. Undo isn't available — the sheet was discarded at save time.

### Set up the protections

8. **File → Options → Save** → AutoRecover every **2** minutes → tick *Keep the last AutoRecovered version*.
9. **File → Options → Formulas** → confirm Calculation is **Automatic**. If a colleague's file ever "stops calculating", this is why — and the setting travels with the file.

<Shot id="1.4.3" />

### Export a PDF

10. Select the range you want. **Page Layout → Print Area → Set Print Area**.
11. **File → Export → Create PDF/XPS** → Options → *Active sheet(s)* → Publish.
12. **Open the PDF and check it** before sending. Every time.

<Shot id="1.4.4" />

## Shortcuts

<ShortcutTable>

| Shortcut | What it does | When to use it | Example |
|---|---|---|---|
| `F12` | Save As | **Converting a CSV to .xlsx** — the most valuable two seconds in this lesson | Also for saving a copy before risky changes |
| `Ctrl` + `S` | Save | Every couple of minutes, reflexively | Especially on a local file with no AutoSave |
| `Ctrl` + `N` | New workbook | Any fresh piece of work | Quick ad-hoc calculation |
| `Ctrl` + `P` | Print preview | Before every print or PDF export | Checking it fits before committing |

</ShortcutTable>

## Watch out

<MistakeTable>

| Mistake | What you see | Fix |
|---|---|---|
| **Building formulas inside a .csv** | Every formula becomes a fixed value, on every save | <Kbd>F12</Kbd> → .xlsx *before* starting work |
| Saving a macro file as .xlsx | Macros silently removed | .xlsm for anything with macros |
| Trusting AutoSave on a local file | AutoSave only works in OneDrive/SharePoint | Check the toggle; press Ctrl+S yourself |
| Opening a CSV with IDs like `0012345` | Leading zeros vanish | Import via **Data → From Text/CSV** and set the column to Text |
| Emailing .xlsx when you wanted a snapshot | Recipients edit it and send back a second version | Export a PDF |
| Calculation left on Manual | Formulas show stale results for days | File → Options → Formulas → Automatic |

</MistakeTable>

<Callout type="story">
**Sandeep, Payroll Executive.** Every month he downloaded the attendance CSV, added twelve columns of overtime and deduction formulas, and saved with <Kbd>Ctrl</Kbd>+<Kbd>S</Kbd>. Excel warned him about CSV limitations each time; he clicked through it because it always appeared.

In month four an auditor asked him to show how a particular overtime figure had been calculated. He opened the file — every cell contained a hard number. No formulas anywhere, for four months. He couldn't reconstruct the logic for any prior month.

Rebuilding took three days. **The fix would have been one keystroke — <Kbd>F12</Kbd>, save as .xlsx — at the start.**
</Callout>

## Practice

<Exercise id="1.4.e1">

<Scenario>
Set up a proper working file from a system export.
</Scenario>

<Dataset name="Expense_Claims">

Create this in Notepad and save it as `expense_export.csv`:

```
ClaimID,EmpID,Category,Amount,Status
C001,E1001,Travel,4500,Approved
C002,E1002,Meals,1200,Pending
C003,E1001,Travel,7800,Approved
C004,E1003,Training,15000,Pending
C005,E1004,Meals,900,Rejected
```

</Dataset>

<Task>

1. Open the CSV in Excel. How many sheet tabs are there?
2. Convert it to `Expense_Claims_Sep2026_v1.xlsx` using <Kbd>F12</Kbd>.
3. Add a sheet named `Summary`. In B2, total the Amount column from the data sheet.
4. Save, close, reopen. Confirm both the sheet and the formula survived.
5. Now save the same file as `.csv` and reopen it. What happened to the Summary sheet and the formula?
6. Set AutoRecover to 2 minutes and confirm Calculation is Automatic.
7. Set a print area on the data and export a PDF. Open the PDF to check it.

</Task>

<Expected>
Step 1: exactly one tab · Step 3: total = 29,400 · Step 4: both survive · Step 5: the Summary sheet is gone entirely, and only the active sheet's values remain
</Expected>

<Solution>

```
Step 3, assuming the data sheet is named expense_export:
B2: =SUM(expense_export!D2:D6)

If the sheet name contains a space, Excel adds apostrophes:
=SUM('Expense Export'!D2:D6)
```

</Solution>

<Why>

**Step 5 is the point of the whole lesson.** CSV is a single-sheet, values-only text format, so Excel discards the extra sheet and every formula without asking twice. It isn't a bug or a limitation you can work around — it's what the format is.

That's why the first action on any downloaded CSV is <Kbd>F12</Kbd> and save as .xlsx. As a bonus, keep the original CSV untouched as your raw source: next month you replace only that file, and the formulas and summaries you built elsewhere keep working.

The `!` in `expense_export!D2:D6` separates a sheet name from a cell address, and you'll use it constantly once workbooks have several tabs.

</Why>

</Exercise>
