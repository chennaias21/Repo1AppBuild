## Why this matters

XLOOKUP is better than VLOOKUP but needs Microsoft 365. INDEX MATCH is just as robust, looks in any direction, and works in every version of Excel ever shipped. If you share files with anyone on an older version — and in most companies you do — this is the combination to know.

## How it works

Two simple functions doing one job each.

**`MATCH` finds the position.** Not the value — the row number within a range.

<FormulaBlock>
```
=MATCH("E1003", $H$2:$H$6, 0)   →  3
       │        │             │
       │        │             └── 0 = exact match. Always.
       │        └───────────────── where to look
       └────────────────────────── what to find
```
</FormulaBlock>

E1003 is the 3rd item in that range, so MATCH returns `3`.

**`INDEX` fetches by position.** Give it a range and a number, it returns that item.

<FormulaBlock>
```
=INDEX($I$2:$I$6, 3)   →  "Rahul Shah"
```
</FormulaBlock>

<Shot id="5.3.1" />

Nest them and MATCH supplies the number INDEX needs:

<FormulaBlock>
```
=INDEX($I$2:$I$6, MATCH(A2, $H$2:$H$6, 0))
       │           │
       │           └── "which row is E1003 in?" → 3
       └────────────── "give me item 3 from the name column"
```
</FormulaBlock>

Read it inside-out: MATCH answers *where*, INDEX answers *what*.

<Callout type="tip">
`F9` makes this click. Select just the `MATCH(...)` part inside your formula and press F9 — it turns into `3`, and suddenly the whole thing reads as `=INDEX($I$2:$I$6,3)`. Press `Esc` to restore. Do this once and the nesting stops feeling abstract.
</Callout>

**Why it's robust:** the return range and the search range are separate arguments, each a direct reference. Insert a column between them and both references adjust. Search on the right and return on the left — INDEX doesn't care which side anything is on.

### Two-way lookup

MATCH can find a column position too. Use two MATCHes for a row-and-column intersection:

<FormulaBlock>
```
=INDEX($B$2:$E$20, MATCH($G$2,$A$2:$A$20,0), MATCH($H$2,$B$1:$E$1,0))
       │            │                          │
       │            │                          └── which COLUMN? (across the header row)
       │            └───────────────────────────── which ROW?
       └────────────────────────────────────────── the whole data block
```
</FormulaBlock>

That's one formula reading any cell of a grid by its row and column labels. Change either label and the answer follows — which is how you build a compact interactive report without a pivot table.

### Build it in pieces first

1. **D2** — just the MATCH: `=MATCH(A2,$H$2:$H$6,0)` → `3`
2. **E2** — just the INDEX, using a typed number: `=INDEX($I$2:$I$6,3)` → `Rahul Shah`
3. Confirm you understand both before combining. This is worth the thirty seconds.

<Shot id="5.3.3" />

### Combine

4. **C2**: `=INDEX($I$2:$I$6,MATCH(A2,$H$2:$H$6,0))` → `Rahul Shah`
5. Fill down.
6. Press <Kbd>F2</Kbd>, select the `MATCH(A2,$H$2:$H$6,0)` portion, press <Kbd>F9</Kbd>. It becomes `3`. Press <Kbd>Esc</Kbd>.

### Look leftwards — the thing VLOOKUP can't do

7. **F2**: given a name in I, return the EmpID from H:
   `=INDEX($H$2:$H$6,MATCH("Kabir Menon",$I$2:$I$6,0))` → `E1005`
8. Note the return range is to the *left* of the search range and nothing complains.

<Shot id="5.3.4" />

### Two-way lookup

9. Build a small grid: regions down A5:A8, quarters across B4:E4, revenue in B5:E8.
10. Put a region name in `G4` and a quarter in `G5`.
11. **G6**: `=INDEX($B$5:$E$8,MATCH($G$4,$A$5:$A$8,0),MATCH($G$5,$B$4:$E$4,0))`
12. Change either label in G4 or G5 and the answer updates. One formula, any cell of the grid.

## Shortcuts

<ShortcutTable>

| Shortcut | What it does | When to use it | Example |
|---|---|---|---|
| `F9` on the MATCH portion | Replaces it with the row number it found | Understanding the nesting, and debugging when the wrong row comes back | Select `MATCH(A2,$H$2:$H$6,0)` → `3` |
| `F4` | Locks ranges to absolute | Both the INDEX range and the MATCH range, before filling down | Select `$I$2:$I$6` |
| `Ctrl` + `[` | Jumps to the cells the formula references | Checking your INDEX range covers the rows you think it does | Click the formula, press Ctrl+[ |

</ShortcutTable>

## Watch out

<MistakeTable>

| Mistake | What you see | Fix |
|---|---|---|
| **INDEX and MATCH ranges different heights** | Wrong row returned, no error | Both must start on the same row and span the same rows |
| MATCH range includes the header | Every result is off by one | Start both ranges at row 2, not row 1 |
| Omitting MATCH's third argument | Defaults to approximate — wrong values on unsorted data | Always `,0)` |
| Ranges not locked | Results drift on lower rows | <Kbd>F4</Kbd> on every range |
| Nesting them the wrong way round | `#VALUE!` or nonsense | INDEX outside, MATCH inside. *Where* feeds *what*. |
| Two-way MATCH on the wrong header range | `#N/A` | The column MATCH searches the header **row**, not a column |
| Trailing spaces or data-type mismatch | `#N/A` | Same as any lookup — `LEN` and `ISNUMBER` |

</MistakeTable>

<Callout type="story">
**Farhan, Finance Analyst, mixed-version office.** He built the quarterly reporting pack with XLOOKUP because it was cleaner. It worked perfectly on his machine.

He sent it to eight regional controllers. Three were on Excel 2019. For them, every lookup in the pack returned `#NAME?` — roughly 400 cells of errors across six sheets. Two of them assumed the file was corrupted and asked for it to be resent. One spent an afternoon trying to repair it.

He rebuilt the pack with INDEX MATCH, which does exactly the same job and works on every version back to Excel 2003. It has been shared unchanged for two years since.

**Choose your lookup for the audience, not for your own machine.** XLOOKUP is the nicer function; INDEX MATCH is the one that arrives working. In a mixed-version organisation, compatibility beats elegance.
</Callout>

## Practice

<Exercise id="5.3.e1">

<Scenario>
Build a lookup pack with INDEX MATCH, including a leftward lookup and a two-way grid reader that will work on any version of Excel.
</Scenario>

<Dataset name="Sales_Transactions" starter="starter/05-03-index-match.xlsx">

**Master** (H:K)

| | H | I | J | K |
|---|---|---|---|---|
| **1** | EmpID | Name | Dept | CTC |
| **2** | E1001 | Anil Kumar | Sales | 640000 |
| **3** | E1002 | Meera Nair | HR | 520000 |
| **4** | E1003 | Rahul Shah | Sales | 810000 |
| **5** | E1004 | Sneha Rao | Finance | 470000 |
| **6** | E1005 | Kabir Menon | Ops | 920000 |

**Revenue grid**

| | A | B | C | D | E |
|---|---|---|---|---|---|
| **10** | Region | Q1 | Q2 | Q3 | Q4 |
| **11** | North | 4200000 | 4650000 | 5100000 | 4890000 |
| **12** | South | 3800000 | 3920000 | 4100000 | 4350000 |
| **13** | East | 2900000 | 3150000 | 3300000 | 3080000 |
| **14** | West | 5100000 | 5400000 | 5250000 | 5800000 |

**Report** — EmpIDs in A2:A6: `E1003`, `E1001`, `E1005`, `E9999`, `E1002`

</Dataset>

<Task>

1. **C2** — the name, using INDEX MATCH. Lock all ranges. Fill down.
2. **D2** — the CTC, same approach.
3. Row 5 has `E9999`. Wrap column C in `IFNA` returning `Not in master`.
4. **F2** — given the name `Sneha Rao`, return her EmpID. Search column I, return column H.
5. Put `South` in **G17** and `Q3` in **G18**. In **G19**, return the revenue at that intersection using a two-way INDEX MATCH.
6. Change G17 to `West` and G18 to `Q1`. Confirm G19 updates to 5,100,000.
7. In **G20**, return the **highest** quarterly revenue for whichever region is named in G17. You'll need MAX over an INDEX-returned row.

</Task>

<Expected>
C2 `Rahul Shah` · C5 `Not in master` · F2 `E1004` · G19 = 4,100,000 for South/Q3 · after step 6, 5,100,000 · G20 for West = 5,800,000
</Expected>

<Hint>
For step 7, `INDEX` with a row number but `0` as the column number returns the whole row as a range — which MAX can then work on.
</Hint>

<Solution>

```
C2: =IFNA(INDEX($I$2:$I$6,MATCH(A2,$H$2:$H$6,0)),"Not in master")
D2: =IFNA(INDEX($K$2:$K$6,MATCH(A2,$H$2:$H$6,0)),0)
F2: =INDEX($H$2:$H$6,MATCH("Sneha Rao",$I$2:$I$6,0))

G19: =INDEX($B$11:$E$14,MATCH($G$17,$A$11:$A$14,0),MATCH($G$18,$B$10:$E$10,0))

G20: =MAX(INDEX($B$11:$E$14,MATCH($G$17,$A$11:$A$14,0),0))
```

</Solution>

<Why>

**Step 7 is the one worth knowing.** Passing `0` as INDEX's column argument returns the **entire row** as a range rather than a single value. `INDEX($B$11:$E$14,4,0)` isn't 4,000-something — it's the whole of B14:E14. That range then feeds any function that takes a range: MAX, MIN, SUM, AVERAGE, even another MATCH.

It's a genuinely useful trick because it lets you do row-level aggregation without hard-coding which row. "Best quarter for whichever region is selected" is one formula, and it follows the dropdown.

**Steps 1 and 4 together prove the direction point.** Step 1 searches column H and returns column I — rightwards. Step 4 searches column I and returns column H — leftwards. The formula is structurally identical; only the two range arguments swap. INDEX has no concept of a "first column", which is the entire limitation that makes VLOOKUP awkward.

**The alignment rule in the mistakes table is the one that bites in real files.** If your MATCH searches `$H$2:$H$6` but your INDEX range is `$I$1:$I$6`, MATCH returns 3 and INDEX fetches the 3rd item of a range that starts one row higher — so you get row 3 instead of row 4. Off by one, every row, no error. Both ranges must start on the same row. When a lookup returns consistently adjacent-but-wrong values, this is almost always why.

**On step 3's fallback choice:** column C gets text, column D gets `0`. Different fallbacks in the same exercise, deliberately — C is read by a human, D is summed. The fallback follows the use, not a habit.

</Why>

</Exercise>
